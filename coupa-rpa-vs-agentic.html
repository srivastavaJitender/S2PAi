Real-world scenarios — how each approach handles them
Click each scenario to see how RPA and agentic AI respond differently
📄 Standard invoice — tax and WHT errors found
RPA: generic holdAgent: contextual hold
⌄
🤖 RPA response
Runs tax → WHT in fixed order. Finds errors. Posts generic template: "Tax validation failed. Please review and resubmit." Sets on-hold. No context. No line-level detail. AP team has to go back into Coupa to figure out what's wrong.
🧠 Agentic AI response
Claude fetches invoice, reads vendor history first. Runs validators it decides are relevant. Writes specific comment: "Line 2: tax rate 20% ≠ IL_VAT_17 master rate 17%. Line 3: WHT IL_Z9_99 not in vendor master — allowed: IL_Z0_00, IL_Z1_10." AP team knows exactly what to fix.
🔄 3rd failure from same vendor in 30 days
RPA: holds againAgent: escalates
⌄
🤖 RPA response
No memory of previous failures. Treats this exactly like invoice 1. Holds it again with the same template comment. AP team sees the same error for the 3rd time. Pattern is never noticed. Vendor master is never corrected. Problem continues indefinitely.
🧠 Agentic AI response
Claude reads vendor_patterns.json — sees 2 prior WHT failures with the same code. Reasons: "Holding won't fix a vendor master data issue." Escalates to AP manager with high urgency, explains the pattern in the comment, recommends vendor master correction. Stores reflection. Problem gets resolved.
❓ Novel situation — invoice type not covered by rules
RPA: wrong actionAgent: handles gracefully
⌄
🤖 RPA response
A credit note arrives — negative amount, different tax treatment. No rule covers it. RPA either crashes, holds it with a wrong error message, or worse — submits it incorrectly. Developer intervention required to add a new rule before the next occurrence.
🧠 Agentic AI response
Claude notices the negative amount and credit note type. Reasons: "Standard tax validation rules do not apply to credit notes — applying them would give false failures." Posts a comment explaining it cannot validate this invoice type and escalates for human review with full context. No developer change needed.
✓ Clean invoice from trusted, well-known vendor
RPA: same full sequenceAgent: efficient path
⌄
🤖 RPA response
Always runs the exact same sequence: extract → tax → WHT → if/else. Same number of steps for McKinsey with 50 clean invoices as for a new high-risk vendor. No efficiency gain. No trust concept. Every invoice costs the same effort.
🧠 Agentic AI response
Claude reads vendor history — 50 clean invoices, 0 failures. Runs core validations efficiently, skips duplicate check and PO tolerance (no signal). Passes quickly, posts brief confirmation, submits. Gets faster and more efficient as vendor trust is established over time.
📈 Large invoice — 3x normal amount, same vendor
RPA: treats sameAgent: applies extra scrutiny
⌄
🤖 RPA response
Invoice amount is not part of validation rules. RPA runs the same tax and WHT checks regardless of whether the invoice is USD 5,000 or USD 500,000. No additional scrutiny triggered. Amount context is invisible to the process.
🧠 Agentic AI response
Claude notices the invoice is significantly larger than historical averages for this vendor. Decides to also run check_duplicate and check_po_tolerance even if not otherwise triggered. Validates that the amount is properly supported by a PO. Adds a note in the Coupa comment flagging the unusual amount for AP awareness.
💡
The key insight: RPA handles the scenario you anticipated. Agentic AI handles the scenario you didn't — because Claude reasons about what it finds, not just what it was told to expect.
